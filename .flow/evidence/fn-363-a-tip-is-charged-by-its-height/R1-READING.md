# fn-363 R1: every reader of a tip's path, read before the change

Builder (Opus), 13 Nov 2026, on `fn-363-a-tip-is-charged-by-its-height` at `9f923410a`. Its crates, `src` and `scripts` are `fn-351-phase-top` (`f17affbb3`) to the byte (`git diff --stat` is empty). This is a reading of the code; nothing here was run.

## The one reader in the product

- `crates/telperion-space/src/grow/cycle/passes.rs`, `Grower::balance_one`, closure `own`: each lit tip is charged `charge(size, p.path_end(), inverse)`, where `size = base_scale * running` and `inverse` is the tip's PA's `inverse_height`. `charge(size, path, inverse_height)` is `size * (path * inverse_height)^2`. Nothing else in the crate calls `charge`.
- **Both engines charge through this one function, so there is no second form.** The production grower (`grow` -> `cycle::grow_cycle` -> `Paused`, `one = true`) calls `open`, `retire`, `balance_one` and `allot_one` every cycle (`grow.rs`, `Grower::step`). The test-only whole-tree engine (`grow::run`, `whole`, `sketch`, `one = false`) balances through the same `open` + `balance_one` wherever `balances()` holds, then allots with `sketch.rs`'s `allot`. That allotment reads no charge. The tests that hold the engines to each other are `grow/cycle/tests.rs` (`the_working_set_and_retirement_leave_the_tree_as_it_was` and its siblings, which compare `reference()`, the whole-tree engine, with the one cycle), `grow/tests.rs` (`whole` against `sketch`, on the same engine) and `grow/cycle/paused/tests.rs`. None of them computes the charge itself.
- **The height is available wherever the charge runs (the spec's second Stop does not apply).** A tip's last laid node is `Grower::tip` (`sketch.rs`): the last phytomer's `tip`, or the axis's `base` where it has laid none. The shade pass already reads the light there for every living apex, in both engines, every cycle a layout exists. The balance runs only when a layout is grown (`balances()` requires `sketch`), and charges only the axes the layout has laid (`apex.axis < pencils.len()`). The layout writes phytomer tips and `pencil.path` in the same step (`draw.rs`), so the height is exactly as current as the path. Axis 0 is the seed: it has no bearer and is never shed or retired, and compaction (`compact.rs`) keeps the order of held axes, so `axes[0].base` stays the root collar's base after records are let go. `Grower::tip` borrows the whole grower, while the closure in `balance_one` holds the sketch mutably. The change therefore reads the same point through a free function over the axes, which `Grower::tip` then calls, so the tip has one definition.

## `path_end` once the charge leaves it

Once the charge reads height, nothing that shapes the tree reads the path. It is read only to build more path: `draw.rs` starts a continuation at its bearer's `path_end()` and a lateral or relay at `path_at(node)`, and pushes `path_end() + length` for each phytomer laid. Outside that, `footprint.rs` counts its bytes and `paused/tests.rs`'s `paths` checks that it survives. It costs one `f32` per phytomer a held pencil has laid, plus `root` per pencil, plus a `Vec` header per pencil. On the oak at 120, seed 1001 (the probe's V4x reader, `OO|store|pencils.path`), that is 5,625,149 entries and 30,529,616 bytes held (29 MiB). It is left in place, as the spec says. Deleting it, with `path_at`, `path_end`, `root`, the `paths` test and the footprint line, is a follow-up for the host.
