**Part 2 is directly buildable. Part 1 needs a foliage-retention contract. Part 3 needs redesign before implementation.** I read all of `TWIGS.md`, its sheet description, and viewed the sheet. This is a static code review; no files changed or tests run.

1. **Age-bound leaves fit the pipeline, but age is unavailable at placement today.**

   Both engines know birth cycles: CPU [`Phytomer::cycle`](crates/telperion-space/src/structure.rs:152), device [`phyts[p + 2] = cycle`](crates/telperion-render/src/generation/fine/apex.wgsl:115). CPU conversion drops that information; the device’s [laid record](crates/telperion-render/src/generation/fine/geometry.wgsl:57) and [dressed record](crates/telperion-render/src/generation/fine/dress.wgsl:70) omit it too. **Engine knowledge does not currently reach foliage placement on either executor.**

   There is another complication: [conversion merges phytomers](crates/telperion-core/src/pipeline/space.rs:429). A drawn segment can contain wood from different years. Assigning only its terminal phytomer’s age would misclassify stations.

   The simplest compatible rule is **existing bearing eligibility × age retention**, with retention `clamp(leaf_years − wood_age, 0, 1)`. Unbounded retention must preserve existing station positions, keys and random draws exactly. Carry eligible spans or station retention through conversion, including merged phytomers; define how fractional retention changes rendered leaves. Switching from radius eligibility to age eligibility only when the value becomes finite would violate continuity.

   Clusters need separate care. [`cluster_leaves`](crates/telperion-space/src/species.rs:145) accepts whole counts and replaces foliage along an entire existing axis with leaves at its tip. It neither creates spurs nor checks whether that tip grew this year ([conversion](crates/telperion-core/src/pipeline/space.rs:510)). Beech already has a [short-shoot PA 14](crates/telperion-core/presets/european-beech.values:468); target that architecture and define retention for stopped tips. “2–3” is a choice between integers, not a continuous dial.

2. **Spacing is a preset change; no new mechanism is needed.**

   [`internodeLength = 0.006`](crates/telperion-core/presets/european-beech.values:63) controls foliage stations, independently of the engine’s [PA internodes](crates/telperion-core/presets/european-beech.values:455). Both executors already count stations in whole micrometres ([CPU](crates/telperion-core/src/pipeline/foliage/plan.rs:150), [device](crates/telperion-render/src/generation/fine/stations.wgsl:92)). **Six millimetres is not an executor-equality requirement.** Changing it to a measured spacing preserves the one pipeline and existing numerical contract; unchanged values preserve bytes. Counts remain discrete at station boundaries.

   The proposed justification overreaches: `TWIGS.md` labels the botanical numbers unsourced, and nothing establishes that old-wood foliage alone caused round 11’s hemlock appearance. Treat 2–4 cm as candidates pending sourcing and stills, and correct the stale comment. Establish age eligibility before judging spacing.

3. **Radius-dependent scaling can preserve connectivity mathematically, but not through the stated two local edits.**

   The connected recurrence is `new_child = new_parent + factor × (old_child − old_parent)`. However, independently multiplying all radius fields breaks their meanings: continuation `start_radius` inherits the parent’s radius, and `base_radius` belongs to the run’s first node ([conversion](crates/telperion-core/src/pipeline/space.rs:470), [run assignment](crates/telperion-core/src/pipeline/space.rs:544)).

   More seriously, CPU converts at natural size and scales afterward, while the device uses scaled coordinates for [inside/behind tests, inherited radii and fork ratios](crates/telperion-render/src/generation/fine/dress.wgsl:339). Uniform scaling preserves these comparisons; varying factors do not. Matching executors would require explicit natural and transformed geometry, matching parent accumulation across wave seams, and consistent grown lengths, radii and stands. Keep the [scale-one early return](crates/telperion-core/src/pipeline/space.rs:122) for neutral byte identity. The current parity test does **not** assert general cross-executor byte identity ([test](crates/telperion-render/src/generation/fine/resident_tests.rs:395)).

   **A cleaner candidate is enlargement through the existing per-PA geometry inputs:** enlarge coarse PAs’ internodes and pipe contributions while fine PAs retain ordinary dimensions, then let the same engine compute attachments and girths. [`Form::pipe`](crates/telperion-space/src/species.rs:219) already propagates contributions into supporting wood. This needs measurement and deliberately revises the [current uniform-scale contract](crates/telperion-core/src/supernatural.rs:40), but avoids a second geometric interpretation after growth. Neither approach creates “more orders”; that requires architecture changes.

I would resolve part 1, tune part 2, then measure whether part 3 remains necessary. That follows [“delete before simplifying”](docs/principles.md:28) and avoids building a deformation system before fixing the natural tree’s foliage.
