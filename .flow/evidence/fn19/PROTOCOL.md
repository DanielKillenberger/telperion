# Comparative botanical geometry protocol — fn19-v1

[protocol.json](protocol.json) is the frozen input contract; [references.json](references.json) is fn19-references-v1. This protocol evaluates mature open-grown Oregon white oak and Norway spruce. It defines an engineering baseline with limited qualitative real references, not biological superiority. Geometry and historical fn9 evidence remain unchanged.

## Inputs and species admission

The JSON contains two species packets and 12 explicit cases: seeds 1/2/3 plus three new seeds per species. `species[].parameters` is the complete generated preset family, not a preset-name-only lookup. Resolve a case by deep-copying that object and changing only `skeleton.seed` to `case.seed`. Record the resolved family in `run.parameters[case_id]`; reject unknown parameters or a backend unable to represent that family. Do not use the current preset defaults in place of frozen parameters. `parameter_species_id` must equal `species_id`, and every case must resolve exactly once.

A stable lowercase species ID maps to its exact scientific name, rank and cultivar; no alias may relabel another taxon. IDs and the whitespace-normalized, case-insensitive `(scientific_name,taxon_rank,cultivar)` tuple must each be unique. A specimen is one seeded realization, not a species template. Version 1 requires exactly the declared twelve cases. Later versions may admit any inventory size; no runner may hardcode these two IDs. A new species must provide at least three fixed and three distinct audited holdout seeds, full parameters, a hashed attributed profile, reference IDs, required anatomy and an explicit preset mapping.

Admission returns the `admission` schema, checking in this order:

1. `invalid-manifest`: schema/type/range failure, duplicate case IDs or seeds within a species, unresolved species/reference/parameter IDs, missing three-plus-three sets, or parameters unsupported by the binding.
2. `duplicate-identity`: an ID or normalized taxon tuple already exists in the receiving cohort.
3. `missing-evidence`: missing/unreadable profile, hash mismatch, unresolved attribution, or no usable real reference for that species. Missing scales with explicit gap records are allowed; their traits stay unassessed.
4. `unsupported-anatomy`: compare every required capability with the actual generator's supported capability map. An unknown preset is not another species. Preserve missing capabilities and leave implementation unmet.
5. `ownership-conflict` or `resource-conflict`: two packets claim a shared write path or generation window without an assigned integration owner/schedule. These are unmet workflow prerequisites, not botanical defects.
6. `admitted`: all prerequisites satisfied. Admission means valid runnable input, never botanical validation. Set `implemented` from verified generator support and keep `botanical_validation=unassessed` until evidence exists. A documentation-only packet may demonstrate parsing or an expected unsupported result; it cannot claim runnable admission with `implemented=false`.

Task 5 owns packet templates and workflow documentation; tasks 2/3 own their validators/runners. All use these schema definitions and semantics. Shared registry/binding/capability work has a named integration owner before parallel species workers begin. Species workers own separate files and output directories; integration rechecks previous species. Flow remains the task tracker.

## Seed freeze and identities

The seed draw was persisted before any new output was generated or inspected. The audit scanned 2,637 seed-bearing text files across main and available worktrees, including fn9 history and active fn13/fn18 evidence, and excluded 87,588 integer tokens conservatively. `seed_audit` records the scope, count, audit digest and key manifest hashes. This proves non-overlap with available recorded inputs, not unrecorded private runs. Recheck newly declared concurrent seeds before generation; any conflict invalidates held-out status and requires a new version, never silent replacement. Failures retain their original seeds. Once observed, these six become regression cases for later tuning.

`baseline_source` identifies the pre-task source at its full Git commit and content hashes. Capture-tool identity is separate: `capture_method` pins fn13's available commit and method files, while each actual run hashes its own adapted runner and binaries. Do not hash a live fn13 worktree as though it were its committed source. No timing window or optimized fn13 implementation is required to use the pinned method.

All hashes are SHA-256 lowercase hex. A file hash covers exact bytes. An identity digest hashes UTF-8 concatenation of lexicographically path-sorted entries `path + NUL + sha256 + LF`. Paths are repository-relative with `/`; no duplicates, traversal or symlinks escaping the relevant root. Source identity includes all consumed generator/binding/config files, including relevant dirty/untracked additions; tool identity includes runner, fixture, metric code and dependency lockfiles. Record generated executable/Wasm artifact bytes independently. A Git revision alone never identifies dirty output. A source file required but unreadable produces a failed run; missing hardware/binary produces unavailable evidence with a reason rather than an invented hash.

Manifest, protocol, reference and conditions hashes cover the exact saved JSON bytes. Protocol/reference changes, new seeds, camera rules or cohort additions create a new version and new files; do not edit a frozen version to repair a run. Schema fragments live under `protocol.schema.$defs`; validate an instance using the fragment as root plus that shared `$defs`, with draft 2020-12. JSON Schema handles shape; the cross-field rules in this document are mandatory validator checks.

## Structural metrics

`protocol.metrics` fixes each definition ID. Numeric values are finite JSON numbers; absent values are `null` with `status=unavailable|failed` and a nonempty reason. A successful metric has a non-null value and `reason=null`; empty required populations do not become zero. Every result declares its unit, definition, evidence IDs and included/excluded support. Operational botanical proxies keep `estimated` status even when computed exactly.

Extend the existing native fn9 measurement module's axis convention: all parent/child tree edges participate; greatest child `start_radius` continues the axis, exact ties choose the lowest node index. Root is order 0; every lateral origin adds one order. This is not a developmental branch-age claim. Report ambiguity on tied continuations and the affected descendant axes. Raw counts retain those axes; qualified distributions exclude ambiguous or degenerate axes with support counts. Do not silently redefine order using `NodeKind` or stored branch IDs.

Length sums each axis's edges. Diameter is a circular centreline proxy, not a measurement of drawn fork collars. Taper interpolates diameters at 10% and 90% of cumulative axis length, reporting both values, distal/proximal ratio and diameter loss per metre. Angles compare the incoming parent and first outgoing lateral tangent; missing root tangent is unavailable. Per-order distributions provide `count,min,max,median,p10,p90`; min/max/quantiles are null for no support. Nearest-rank p10/p90 and midpoint median are fixed in JSON. Keep per-axis samples and excluded reasons so analytic fixtures can explain aggregates.

Foliage bins count the centroid of each retained biological unit. Use the native biological prototype subset to exclude connectors; one needle is one unit. Publish the 4×4 height/radius table, both marginals, included total, under/overflow and bin support, alongside normalization bounds. Boundary 1 belongs to the final bin. An empty crown or zero height/radius span is unavailable. Counts are neither area nor a biological pass threshold. Real-reference sources currently provide no matched distribution thresholds.

## Cameras and anatomical targets

A benchmark-only rig can use `TreeEngine.build(...,{surface:true,foliage:true,structure:true})`, original instance matrices and the existing neutral capture approach. Production generator edits are unnecessary. Use orthographic 1600×1000 physical pixels, DPR 1, Y-up, original world-metre geometry, no wind, LOD, texture, ground, scale figure or shadows. Beauty retains all connected wood and foliage; bare hides only foliage. Do not isolate a leaf to claim a connected shoot.

Prepare `conditions.json` from the pinned baseline **once**, under these rules, before examining any candidate. Its top-level shape is `{schema_version:1,benchmark_id,source_sha256,entries:[conditions...]}`. Each entry follows the `conditions` schema. Whole/bare have azimuths 0 and 90 degrees; base/fork/attached-shoot have azimuth 0. That is seven views per case, 84 total. The view direction is normalized `(0.62,0.28,1)` rotated about Y by azimuth; up is `(0,1,0)`. Projection follows the common fixed direction rather than an optimized view of each revision.

For whole and bare, project the complete baseline wood+retained-foliage bounds into the camera plane. Aim at their centre; choose vertical span `1.3*max(projected_height,projected_width/1.6)` and horizontal span `1.6*vertical_span`. Both states share exactly the same camera. Place the camera beyond the complete depth interval and set near/far to enclose it with at least one metre margin. Save exact coordinates, frustum planes and metres/pixel (`vertical_span/1000`). Candidate capture reuses them without recentering or refitting. Empty/nonfinite bounds are failures; a candidate no longer fitting has `clipped-subject`, not an improved crop.

Targets use baseline biological crown bounds for normalization: x/z are relative to root divided by maximum horizontal crown radius, y is relative to crown bottom divided by crown height. Record the query and selected world position. Base is root + `(0,0.5m,0)`, with vertical span 3m. Fork selects an order-1 lateral origin nearest query `(0.25,0.35,0.25)` with an incoming parent edge, two outgoing children, and nondegenerate directions; use vertical span `max(1m,12*parent_diameter)`. Attached shoot selects a terminal twig with retained foliage and a connected parent nearest `(0.7,0.5,0.7)`; target its parent/twig junction and use vertical span `max(0.25m,2*twig_length+2*maximum_unit_length)`. Distances use normalized Euclidean coordinates; ties use ascending world `(y,x,z)` then node index. No eligible target returns `unresolvable-target`.

Local cameras use the same direction and aspect ratio. Set near/far from complete tree depth, never cut away surrounding branches to expose a target. Preserve complete parent attachment and at least one child interval inside the local viewport; local crop of unrelated distant geometry is expected, clipping the named attachment is not. Save selected node IDs only as evidence within that geometry. Candidate topology may differ: rerun the semantic query against candidate nodes using the **baseline normalization bounds**, then verify the selected anatomy fits the unchanged camera. A moved/absent target is explicitly unresolvable or clipped; stale node IDs never establish a match. Candidate-selected positions are saved in its capture receipt, not written into frozen conditions. Visible occlusion yields `occluded-target` and unassessed anatomy, even if capture bytes are complete.

## Crown masks and rendering convergence

Only whole views produce gap metrics. Mask rendering hides wood and draws every original retained biological foliage unit white over black using linear coverage, not a green-channel threshold from beauty images. A pixel's value is a [0,1] multisample coverage fraction. Preserve native, 64-sample and 128-sample arrays and previews. Reuse fn13 Halton `(2,3)` physical-pixel offsets and arithmetic linear averaging; zero jitter must equal native rendering. For each complete image, compare 64 versus 128: linear beauty RMSE ≤0.005 and maximum absolute mean coverage difference over each 16×16 tile ≤0.015. Incomplete tiles use their actual size. Nonfinite arrays, wrong length or failed convergence cannot produce gap results. Store raw float32 little-endian values; PNG previews alone do not establish linear convergence.

For each baseline whole camera, project all retained **biological-unit vertices**, excluding peg/petiole connectors, into pixel coordinates. Their two-dimensional convex hull is the fixed crown ROI; no morphological closing, candidate-derived hull or hand-painted mask. Rasterize pixel centres inside or on the hull into a binary ROI. Empty/collinear hull, zero area, or any projected crown touching/crossing the viewport edge is invalid. Save polygon, raster bytes/hash, camera and baseline geometry identity. The candidate uses exactly this ROI and camera; a different crop, ROI hash or physical resolution is `roi-mismatch`. Report occupied candidate pixels outside this ROI separately as `outside_roi_pixels` and fraction of total candidate occupied pixels. Geometry beyond the viewport is a capture failure; growth outside the baseline hull is an explicit shape change, not silently discarded evidence.

At threshold 0.5, occupied pixels satisfy coverage ≥ threshold; unoccupied ROI pixels are gaps. Pixels outside ROI are excluded from every denominator. Connected gap components use 4-neighbour adjacency. A gap component is an **exterior opening** if any member has a 4-neighbour outside the ROI; all other gap components are **enclosed holes**. Foreground connectivity is 8 for any reported foreground component count. No area filter removes small holes. Publish ROI/occupied/exterior/enclosed pixel counts, ratios to ROI area, hole count, largest hole area in pixels and m², and area histograms with edges `[1,4,16,64,256,1024,+infinity)` pixels. Projected m² equals pixel count × metres/pixel². Report four height bands using ROI min/max pixel-centre Y, lower botanical height first; empty band ratios are unavailable.

Repeat component/count statistics at thresholds 0.25 and 0.75 and report their differences from 0.5; threshold-sensitive holes are visible uncertainty. Zero candidate coverage is `empty-crown`, never a favorable open crown. Analytic controls must exercise an enclosed hole, an exterior notch, diagonal-only connectivity, threshold-sensitive closure, an empty crown, clipped geometry and changed crop/ROI. None may generate a biological pass. Coverage, holes and openings have **no preferred numerical direction**: they describe projected silhouettes, not 3-D voids, leaf area, or superior fidelity.

## Receipts, failures and replay

Use a new output directory for every run; require it not to exist, resolve containment and write only underneath it. Never repair a receipt in an old run. `run.json` follows `run`; `measurements.jsonl` contains `case_result` events; `captures.json` is an array of `capture`; `comparison.json` follows `comparison`; `assessment.json` is an array of `assessment`. The explicit case manifest is the JSON array copied from `protocol.cases`, saved and hashed before execution. Independent workers can emit numeric and visual runs separately, tied by identical manifest/protocol/reference/parameter identities and a shared frozen conditions file.

Flush `pending` records for every required case before running the first. Flush `started` before work and a terminal record after artifact hashes are available. An unterminated final JSONL line is ignored after interruption; pending/started without terminal completion remains interrupted/unassessed. A `pass` capture requires non-null camera/target/geometry/conditions identities; preflight failure may leave those null with a reason. A final run `complete` means every required artifact and terminal case exists and verifies; unavailable/failed required evidence prevents full completion. Partial runs set `partial=true` and never claim cohort completion. Process bounds are 300000ms per case; resource caps and timeouts retain their cases and reasons rather than reducing fidelity.

`numeric_status=pass` means the specified numeric collection and integrity checks succeeded, including proxy outputs; it is not a botanical verdict. A required failed metric means fail; a required unavailable metric means unassessed. `capture_status=pass` requires decoded nonempty PNGs, raw arrays where required, matching dimensions and verified hashes, plus camera/anatomy framing postconditions. Rendering convergence, `visual_status`, `assessment`, `expert_status` and `owner_feedback` remain distinct. A successfully rendered but occluded view can have a complete capture and unassessed trait with a reason. No local geometry ID or internally consistent camera alone proves visible anatomy.

Every referenced artifact must have a nonzero byte count, relative contained path, MIME type and SHA-256. A failure before geometry/camera creation is represented by nullable camera/target/geometry/conditions identity in capture, with no successful artifact claim. For reuse, a new run may reference old complete artifacts only by verified identity through its manifest; symlink/path escapes and unhashed external output are rejected. Missing assets, mismatch, nonfinite geometry, truncation, unsupported anatomy and unavailable hardware are separate reason codes. Null is never numeric zero.

Revision comparison first checks all `comparison_equal_fields`, complete case sets and per-view condition identity. Record tool identities; differing tool content makes comparison inconclusive unless the identical metric/capture implementation is replayed for both sources. Source and geometry output hashes may differ by design; counts and bounds are observations, never required equality. Report all failed/missing cases with reasons and no aggregate that hides them. Changed conditions require another benchmark version. Biological comparison remains limited by the inventory and actual independent assessment; this protocol never emits an automatic superiority verdict.

Costs are distinct `cost` records: native generation, capture preparation, CPU RSS, Wasm capacity, estimated GPU allocation and measured GPU time. Unknown values are null with reasons. Record hardware, OS, tool versions, lifecycle/warmup/sample counts, and whether the resource window was exclusive. A qualified timing comparison requires equivalent lifecycle conditions, all valid samples and an exclusive window coordinated with fn13/fn18. Contended or unmatched timings remain observations/inconclusive; no performance target is introduced.

## Independent assessment packet

Prepare a fixed packet covering every case/view and every missing or failed item. For each trait, ask for `supported`, `contradicted` or `unassessed`, evidence IDs and rationale. Traits are: species crown habit; scaffold hierarchy and local taper; base/fork surface continuity; connected shoot organization and organ identity; visible surface detail; rendering artifacts/occlusion. Keep biological plausibility, woody surface detail and rendering errors separate. No numerical proxy substitutes for these observations.

An independent reviewer identifies role, relevant botanical/arboricultural expertise, relation to the implementation and original feedback. An implementation worker's own inspection is labeled as such; it is not independent expertise. Neutral A/B labels may hide generator name, source revision and expected winner while preserving species, context, view, dimensions and leaf state. Retain attribution and the A/B-to-source mapping in the evidence packet; do not erase copyright marks from source imagery. No external contact is part of this protocol. Without qualified independent feedback, `expert_status=unassessed`, R3 remains unresolved in that respect, and biological superiority stays unestablished.
