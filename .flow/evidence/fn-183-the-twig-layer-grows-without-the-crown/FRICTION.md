# fn-183 friction

## 2026-10-02, task .1 (R1 ladder measurement)

- **A shell-safety hook refused the measurement driver.** I was writing the driver for 150 measured runs as a heredoc that reset its three output files with `: > "$R/..."`. The local `dcg` hook blocks truncating redirects to paths it cannot resolve. Cost: about 2 minutes and one rewrite with literal paths and append-only output. What would remove it: nothing in the repository. It is local setup and is reported here, not specced.
- **The lower-surface search was hidden inside "bisection" in the earlier count.** QUERY-COUNTS.md split the birch's queries by the call site that opened them, so 1.12M curtain-band queries showed up as stride and bisection queries. Cost: none to this task, since the exclusive purpose scope separates them. It is recorded because fn-174's scope was set from the earlier attribution.
- **Counting changes the time it counts.** The `query-count` build takes about 40% longer on the oak (63 to 66 ms against 47 ms), so timings come from a second binary built without the feature. Cost: one extra build of about 20 s per code change. What would remove it: nothing. This is the reason the counters compile out.

## 2026-10-02, task .2 (build rung 1)

- **Rung 1 breaks consumers and rows that assumed the wall, and R1 never ran the suite.** The production change (three edits: planner stride check and bisection, terminal admission, both kept on the growth path only) reproduces rung 1 byte for byte (tree hash and node count match `c4950378` at `LADDER=1` for all five presets at seeds 1 and 7). `cargo test --profile ci -p telperion-core --lib` then fails 24 tests. Most are pins or containment asserts the decision retires, but four are not test edits: the packed-leaf box (`foliage/reference.rs`, "the authored shell bounds the wood") is now too small, so oak leaves clamp onto its wall and move up to 17 mm against a 0.4 mm step; the field leaves 648 of 981,719 oak leaf vertices in no foliage cell; the hang row walk changes the birch from 70,238 to 52,650 nodes at hang 0.1 (the "one continuous tree space" check); and sagging curtain axes now pass the curtain floor (0.961 m against a 1 m clearance; 0.98 m against a 2.16 m crown base when the clearance is above it), since only terminal twigs are checked against `below`. Each needs a design answer, so the task stops with NEEDS_HUMAN. Cost: about 15 minutes and one 90 s suite run. What would have removed it: running the lib suite on the exploration binary in R1, so the decision record would have named these consumers.

## 2026-10-02, task .2, second pass (after the host's decisions)

- **Three more questions surfaced only once the first four were fixed.** Each suite run takes about 90 s and its failures hide behind earlier ones in the same test: the oak's width gate sat behind its containment assert, and the catalogue `pins.json` check sat behind the identity pins. The three: the drop walk's strict monotonicity, a collapse fixture no seed reproduces, and the oak's crown width no longer varying by seed. Cost: about 5 suite runs (8 minutes) and two seed searches (45 s). What would have removed it: one `--no-fail-fast` lib run on the exploration commit in R1, read assertion by assertion rather than test by test.
- **The pins live in four places.** These are `species/digests.json`, the `identity.rs` `PINS`, `catalogue/<id>/pins.json`, and three suites' `NEUTRAL` arrays (`drop`, `sag`, `strands`), plus `audit.rs`. Only some have a print helper, and the species digests had to be parsed from the failure text. Cost: about 10 minutes. What would have removed it: one `print_pins`-style recorder that rewrites every pin file from one run.

Cost: one extra 307 s gate run and three re-pin passes. What would remove it: a pin recorder covering every pin file, including the `telperion-jev` palm record and the fn-24 still, and a note in the gate docs naming the cross-crate pins a generator change moves.

Cost: none here, but the test stays red until a live `--record` run. What would remove it: keying the vision request by the reference photograph and the camera candidates rather than the render bytes, or documenting the re-record as part of any change that moves a tree.
- **The worktree had no `node_modules`,** so the first `npm test` stopped after the catalogue check (which also caught stale pages). Cost: one `npm ci` and about 1 minute. Local setup; not specced.

## 2026-10-02, task .2, palm apex (stop)

- **The cleared twig layer leaves a trace in the drawn palm.** Skipping the apex's twig layer cannot be byte-identical to the current branch. `finish` (`branching.rs`) tapers a childless structural apex to the twig tip radius. The twigs that are grown and then cleared make the apex count as having children, so today its distal radius stays at 0.240 m; without them it tapers to 0.0035 m. The 512 leaf bases are hung from those radii, so 256 of them move by up to 7 cm. The base already showed both outcomes: at seed 1 the wall let nothing grow, which gave the tapered apex (hash `52be2bb8`, the same as the skip), and at seed 7 some twigs grew, which gave the thick one. Cost: about 15 minutes. Stopped with NEEDS_HUMAN, because which apex the palm should draw is a design choice.
