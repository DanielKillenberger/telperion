## Measured browser regression

[Structured measurements and provenance](AUDIT-2026-10-26.json). Dedicated module workers, headless Chromium build 1243, NVIDIA Ampere through Vulkan, sequential 36³ fields. First run uses seeds 1 and 1234; repeat uses seed 1 twice. Localhost assets, no network throttling. Generation includes grid extraction and owned JS answers, excludes preparation and voxelization. This is a small diagnostic sample, not statistical release qualification or a visual-equivalence comparison.

| Species | 0.1.4 | Installed prerelease | Repeat observation |
|---|---:|---:|---|
| Oak | 233–260 ms | 355–642 ms | Seed 1 settled to 313 ms; first new-version tree was slowest |
| Birch | 239–304 ms | 254–282 ms | Roughly comparable |
| Spruce | 203–212 ms | 503–539 ms | About 510 ms on repeat, around 2.5× old |

Preparation took 12.8 s in the first browser and 1.0 s in a subsequent fresh browser. This is cache-sensitive, not a guaranteed visitor latency. Field Wasm grew from 344,798 to 3,518,285 raw bytes, or 107,663 to 834,077 Brotli bytes (7.7×). New-version voxelization took roughly 1–3 ms. Family JSON serialization took about 0.05 ms per tree. Neither cube conversion nor JSON is a leading optimization target.

The site now serializes grows through one worker after four WebGPU workers exhausted memory. Earlier site evidence reports 31/31 successful trees in 13.2 s with one worker versus five OOM failures among 35 trees with four. Those are historical consumer measurements, not this audit's paired benchmark. The grove also added species and legendary trees, so total-page comparisons must control the requested content.

## Bounded release recommendations

| Package | Work | Scope and qualification |
|---|---|---|
| 1. Field startup | Compile only programs the field consumes. Remove eager curve/sweep/ring and unused rendering-program preparation. | Medium, about 1–2 tasks. Paired cold preparation/first-tree measurement, unchanged field answers, renderer readiness preserved. |
| 2. Consumer warm-up | Replace killenberger.com's unused n12 birch with `prepareField()` in the worker that will grow visible trees. | Small consumer task. Measure first visible tree and complete grove. |
| 3. Validation parity | Apply canopy range checks and the counted instance budget to the device field. | Small library task. Both reproduced inputs below must reject through both entries. |
| 4. Typed API boundary | Make renderer entry points accept `Family` and serialize internally; share CPU/GPU field types. | Small-to-medium wrapper/caller task, no engine rewrite. |
| 5. Initialization and qualification | Restore default `compileField()` memoization; fix CI receipt inputs; retain a packaged browser benchmark. | Small tasks. Concurrent initialization, receipt invalidation, cold/warm consumer measurements. |

Startup, API/validation, and consumer changes can be worked independently, followed by integrated qualification. These bounded changes do not establish that a 510 ms spruce can become a 200 ms spruce. If old per-tree speed is a hard release requirement, the deeper growth work cannot honestly be deferred.

### Findings and source anchors

1. **Unused field startup programs.** `crates/telperion-render/src/generation/resident.rs:46` calls `curve::passes` during preparation; `curve.rs:36` defines eleven surfacing passes. `generation/resident/build.rs:44` constructs sweep/ring tools. The field explicitly bypasses the wood sweep in `resident/field/make.rs:75`. Confirmed unnecessary initialization; savings from removing it are unmeasured. Formal P2, both completed reviewers.
2. **Fake warm-up.** Consumer `src/lib/grove/client.ts:193` grows and caches a birch at n12. Grid resolution does not reduce botanical growth: `resident/field/make.rs:60` grows the whole tree. Preparation should not manufacture an unused specimen. Consumer finding, not a Telperion source patch.
3. **Validation differs between executors.** Reproduced on Ordinary, seed 1, n12. `canopy.maxInstances=1` rejects on CPU with `foliage instance budget`, while GPU returns a tree. Separately, `canopy.scatter=-1` rejects on CPU with `scatter`, while GPU returns a tree. Source `resident/field/make.rs:95`; reuse applicable canopy checks and enforce counted stations. Formal P2, fn-317 R1 incomplete.
4. **JSON exposed in the renderer API.** `src/browser/render.ts:194` takes strings in `setTree`, `setTreeGpu`, `admission`, and `beginGrowth`; `TreeEngine.build` and `growField` take `Family`. Use the existing `wire` serializer behind the public renderer wrapper. CPU `FieldFrame`/`FieldQuery` and GPU `Grid`/`FieldAnswer` duplicate equivalent shapes; give them one definition.
5. **Lost compile memoization.** `src/field/index.ts:108` says compile once but repeats default compilation. A direct concurrent-call check returned identical modules for 0.1.4 and distinct modules for next. The site already caches its promise, so this does not explain its principal slowdown.
6. **CI receipt omits test inputs.** `scripts/ci-key.mjs:29` omits `docs/parameters.md` and `src/browser/parameters.generated.ts`, read by core parameter-reference tests. The integration reviewer checked that changing either input leaves the core key unchanged. Docs-only edits are also filtered out of the workflow. Include both inputs and allow the parameter reference through the workflow filters. Formal P2.

## Post-release roadmap

1. **Lean field artifact, fn-242.** Make rendering code unreachable from a field-only artifact while preserving the same botanical pipeline. Eager shader preparation and Wasm download size are separate costs; fix each at its own boundary.
2. **Actual growth cost, fn-285.** Reprofile the current browser path, starting with spruce and then the legendary trees. Historical profiles rank growth first, but several old bottlenecks have already been fixed. Preserve botanical growth and qualify gains against supported views. Do not revive rejected approximations without a new bounded oracle.
3. **Produce only consumed representations.** The synchronous `WebRenderer::set_tree` (`web.rs:227`) calls `mesh::build`; `pipeline.rs:75` requests CPU indexed wood and a curve, while `telperion-render/src/lib.rs:246` uploads the curve. Stop tessellating the unused CPU surface for this consumer; retain it for callers requesting that output. This does not affect the site's field path. Formal P2.
4. **Reduce flowers on the GPU.** `resident/florets.rs:130` reads all packed florets into CPU `Instances`; `resident/field/make.rs` computes their bounds and counts them into the grid on CPU. Historical Laurelin counts imply 7,904,880 bytes of floret transfer. Historical native timing attributes about +1%, so this is not established as the main browser regression. Reduce seat bounds and cell counts on-device. Formal P2, fn-257 R8 incomplete. Before release, either fix the implementation or explicitly defer the constraint and correct the “only the grid is read back” documentation; do not leave it marked fulfilled. This audit does not grant that deferral.
5. **Explicit GPU lifetime and budget.** Replace hidden module-global ownership and per-call `source` options ignored after first initialization with an explicit runtime lifecycle. Include disposal, bounded scheduling, cancellation and an explicit memory budget. The browser budget currently derives from a 10 GB reference card (`resident/budget.rs`). Multiple workers must not independently assume ownership of the same physical GPU's memory.
6. **Grow once, sample repeatedly.** Every grid request currently regrows the tree. Introduce bounded reusable specimen ownership for multiple readouts/outputs with explicit release. Resolution-aware work inside the botanical pipeline is a larger research direction that needs a measured error bound, not another generator.
7. **Existing integration contracts.** GPU pregeneration is fn-318; executor agreement is fn-300; shared validation is fn-307. Pregeneration improves delivery but is not a live-generation speed gain.

One bounded probe may be worth taking earlier: `resident/build.rs:105` fences the device for stage timings even when the field discards those timings (`resident/field/make.rs:73`). Measure whether redundant profiling waits can disappear while preserving resource accounting. Savings and safe removal are unproven; do not delete synchronization indiscriminately.

The intended direction is one botanical state, optional outputs, explicit resource ownership, and a consumer for every expensive intermediate.
